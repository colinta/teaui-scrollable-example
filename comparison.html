Implementation comparison

Ink vs TeaUI
scroll views

The two demos produce the same two-axis scrolling experience, but TeaUI can express it with a much smaller layout.

In one sentence: Ink assembles scrolling from measurement, clipping, state, and content offsets; TeaUI delegates all of those mechanics to Scrollable.

Architecture

Ink: compose low-level primitives

  1. useBoxMetrics(viewportRef)
    Measure the border’s client area.
  2. useBoxMetrics(contentRef)
    Measure the natural 140×40 content.
  3. React state
    Clamp requested X/Y against calculated maxima.
  4. Box contentOffsetX/Y
    Translate children and clip hidden overflow.

TeaUI: use the scrolling primitive

  1. Box flex={1}
    Fill the space above the footer and draw the rounded border.
  2. Scrollable
    Measure, translate, clip, and clamp the content.
  3. scrollBy(dx, dy)
    Connect arrow keys directly to the component.
  4. Text footer
    A normal sibling stays fixed below the scrolling region.

TeaUI · index.tsx
const scrollable =
  useRef<ScrollableView>(null)

<Stack.down>
  <Box border="rounded" flex={1}>
    <Scrollable.down
      ref={scrollable}
      contentSize={{width: 140, height: 40}}
      showScrollbars={false}
    >
      {children}
    </Scrollable.down>
  </Box>
  <Text>arrows to scroll, q to quit</Text>
</Stack.down>

Keyboard input

Ink · useInput hooks
useInput((_input, key) => {
  if (key.upArrow)    scrollY(-1)
  if (key.downArrow)  scrollY(1)
  if (key.leftArrow)  scrollX(-2)
  if (key.rightArrow) scrollX(2)
})

const {exit} = useApp()
useInput(input => {
  if (input === 'q') exit()
})
TeaUI · Keyboard fallback
const handleKey = useCallback(event => {
  switch (event.name) {
    case 'up':
      scrollable.current?.scrollBy(0, -1)
      break
    case 'down':
      scrollable.current?.scrollBy(0, 1)
      break
    case 'left':
      scrollable.current?.scrollBy(-2, 0)
      break
    case 'right':
      scrollable.current?.scrollBy(2, 0)
      break
    case 'q':
      screen?.exit()
  }
}, [])

Behavior and trade-offs

ConcernInk exampleTeaUI port
React model React renderer with standard hooks. React reconciler over TeaUI core views.
Terminal mode Live region in the normal terminal output. Fullscreen alternate-screen application.
Scrolling primitive Built manually from overflow and contentOffsetX/Y. Built-in Scrollable component with imperative scrollBy().
Measurement Both viewport and content are measured with refs. Scrollable measures its flex-assigned viewport and children internally; the demo declares a 140×40 extent.
Natural content size flexShrink={0} prevents Yoga from squeezing content. Scrollable lays out children in its larger content region.
Clipping overflow="hidden" clips to the border’s client area. Scrollable creates and clips its own offset viewport inside a rounded Box.
Resize safety Effective offsets are clamped on every render. Scrollable recalculates and clamps its own bounds during layout.
Mouse No mouse handling in the example. Mouse-wheel support comes from Scrollable; visual scrollbars are disabled.
Rendering cost All 40 rows remain mounted and laid out. All rows remain mounted; TeaUI skips drawing fully offscreen children.
Exit useApp().exit() screen.exit()

Parity checklist

✓ LayoutA bordered 140×40 content area scrolls in all space above the fixed footer.
✓ NavigationVertical step 1; horizontal step 2; bounded on every edge.
✓ ResponsiveScrollable updates and clamps itself when the terminal resizes.
✓ PresentationRounded border, hidden scrollbars, a compact fixed help line, and q-to-quit.
